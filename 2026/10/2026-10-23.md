1. Stable Token-level Scheduling for Serverless LLM Inference
论文链接: https://arxiv.org/abs/2610.17689
发布时间: 2026-10-20
类别: cs.AI
论文总结: Serverless LLM 推理弹性扩缩、共享 GPU 池能降本增效，但现有调度大多只优化 TTFT，忽略解码阶段逐 token 延迟（ITL）。论文观察到新请求准入会打断正在进行的解码、推高全体 ITL，提出 Token Window Pacing（TWP）：基于 ITL、队列深度等运行时反馈，在 token 粒度上闭环调节请求准入，并配合分块 prefill 降低新请求干扰。在真实 serverless 负载上，TWP 吞吐较 ServerlessLLM 提升最高 45%，较传统调度提升 58%，显著压低 P99 尾延迟与 ITL 波动，且无需改动模型与内核。
亮点: 用运行时反馈做 token 级准入控制，让 serverless 推理在高并发突发下也能保持稳定的流式体验。

二、KV Cache 复用相关学术论文
1. Range: Decoupling KV-Cache Reuse Granularity from Storage Work
论文链接: https://arxiv.org/abs/2610.21241
发布时间: 2026-10-22
类别: cs.OS
论文总结: 长上下文把 KV Cache 挤到 NVMe SSD 后，前缀恢复进入 TTFT 关键路径。作者测量发现瓶颈并非 SSD 或 CPU 发起 I/O，而是存储栈每一层都按"逻辑对象"计费：同样 6 GiB 前缀按 192 个对象恢复需 2.1 秒，按 6144 个对象需 3.0 秒，分层加载和张量并行会进一步放大对象数。论文提出面向 vLLM 和 LMCache 的存储引擎 Range：Range tickets 取代逐 key 索引、物理字节条带让盘上布局与复用粒度解耦、完成态 GPU 传输 bank 批量投递，使 6 GiB 恢复的中位 TTFT 在对象数变化 32 倍时稳定在 1.79-1.80 秒，距前缀常驻 GPU 仅差 70 毫秒，且只改动 vLLM 四行代码。
亮点: 首次把"每对象开销"确立为 SSD KV 复用的真瓶颈，让细粒度 KV 复用不再以牺牲恢复速度为代价。

三、推理 Infra 相关学术论文
1. An Optical KV Cache Network for Disaggregated LLM Serving
论文链接: https://arxiv.org/abs/2610.18444
发布时间: 2026-10-21
类别: cs.NI
论文总结: P/D 分离架构下每个请求的 KV Cache 都要从 prefill GPU 迁往 decode GPU，编码智能体场景还常迁移整个长上下文，在超额订阅的分组网络中显著增加 TTFT。论文提出用光交换机（OCS）为每次 KV 传输提供满速率专用电路：通过预留调度器在 prefill 计算期间就提交电路，把机械 OCS 10-50 毫秒的重配置延迟藏进 prefill 时间窗，同时每块 GPU 经单纤对的 WDM 光模块接入 OCS。基于真实服务 trace 与 H100 实测 prefill 时间的仿真显示，该光 KV 网络可匹敌带自适应路由的 400G 分组网络，成本仅为 2:1 分组网络的 0.55-0.78 倍，智能体场景 SLO 达标率提升 2.7 至 10.7 个百分点。
亮点: 让光路重配置与 prefill 计算重叠，用更便宜的光交换替代无阻塞电分组网承担 KV 迁移流量。

五、Vibe Coding 实践
1. 第三次解释同一件事时，就把它写成 Skill
问题描述: 用 AI 编码智能体协作时，同一套流程（部署步骤、代码规范、调试套路）往往要反复口头解释，上下文越堆越长，换个会话或模型又得重来，且解释细节容易丢失、执行不稳定。
具体做法: 遵循"三次法则"：第一次向智能体解释某个流程时直接说清即可；第二次发现自己在重复解释时，留意识别这类重复；第三次就把该流程沉淀为项目里的 SKILL.md（含步骤、成功/失败判定和更新说明），智能体按需加载，AGENTS.md 保持精简。流程变更时只需更新 Skill 一处。该实践出自 Vonage 开发者博客 Beyond Vibe Coding: Best Practices in 2026：https://developer.vonage.com/en/blog/beyond-vibe-coding-best-practices-2026
