1. DualPace: Decoupled Scheduling and Cooperative GPU--CPU Decoding for LLM Serving
论文链接：https://arxiv.org/abs/2610.33501
发布时间：2026-10-24
类别：cs.DC; cs.LG
论文总结：LLM 服务依赖批处理提升吞吐，但 KV cache 随序列增长限制 GPU 常驻并发；CPU 卸载虽可扩展 KV 容量，现有系统却受 GPU 调度门控，CPU 侧请求推进呈突发式，尾延迟偏高。DualPace 将主机升级为可独立调度的解码引擎：GPU 引擎负责 prefill 与 GPU 常驻解码，开启 AMX 的 CPU 引擎独立批处理推进 CPU 常驻解码，两者调度解耦、执行协作，必要时调用 GPU 协助稠密计算。评测显示，解码为主场景下吞吐较 NEO 提升 6.9-43.2%，较 vLLM 提升 11.5-90.6% 且延迟持平。
亮点：把 CPU 从 GPU 的附属卸载层变成独立调度的解码引擎，首次实现 GPU/CPU 双引擎解耦协作服务。

二、KV Cache 复用相关学术论文
1. Visual Cache Reuse for Efficient Multimodal Inference（VisMemo）
论文链接：https://arxiv.org/abs/2610.25136
发布时间：2026-10-18
类别：cs.OS
论文总结：VLM 推理因长视觉 token 序列带来高 prefill 延迟与显存开销，现有系统多依赖精确前缀缓存，忽略近似复用的潜力，而直接复用近似缓存会引入虚假视觉信息。VisMemo 以系统-算法协同设计实现近似 KV cache 复用：用 patch 熵识别可复用候选，用 warmup attention 按当前查询优先重算关键 token；并在 GPU、CPU、SSD 三层介质上对精确与近似命中采用差异化 I/O 与缓存策略，消除冗余缓存与不必要的数据搬运。真实生产 trace 上整体缓存命中率从 27.78% 提升至 61.45%，8K 输入下 prefill 延迟最高降低 48.3%。
亮点：首次在多模态服务中系统化引入近似 KV cache 复用，用 patch 熵与注意力预热控制近似复用的质量风险。

五、Vibe Coding 的 Nice Practice
1. 第三次才写 Skill：让代理记住流程而不是塞满上下文
来源链接：https://developer.vonage.com/en/blog/beyond-vibe-coding-best-practices-2026
问题描述：与 AI 编码代理协作时，同样的操作流程（如新增一条 API 路由并补类型、测试和文档）往往要反复用自然语言解释，既浪费上下文窗口，也容易让代理每次执行得不一致。
具体做法：第一次遇到时口头向代理讲清流程即可；第二次发现又在重复解释时先留意记录；第三次就把该流程沉淀为独立的 SKILL.md 文件，代理按需加载。这样 AGENTS.md 保持精简，流程变更时只需更新 Skill 一处。
