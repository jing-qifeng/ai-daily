类别: cs.PF（ACM SIGMETRICS 2027）

论文总结: 大规模部署 LLM 推理需同时选择硬件布局、并行策略、调度与路由，这些决策相互耦合，直接在 GPU 集群上试错成本高昂。本文提出纯 CPU 的确定性离散事件模拟器 BLIS，完整建模准入控制、路由、调度、prefill/decode 执行与 KV 缓存管理，借助全局拟合的解析基函数预测时延，无需按模型或 GPU 单独剖析。跨 6 个模型、3 种 GPU 的 36 组实验中端到端中位误差仅 6.7%，速度约为真实执行的 200 倍；模拟演化出的准入与流控策略已合入开源平台 llm-d。
亮点: 不用 GPU 就能高保真模拟完整推理服务管线，找出的策略可直接落地 llm-d，关键档 TTFT P90 最高降低 82%。
二、KV Cache 复用相关学术论文
1. KVCompass: A Discovery Plane for Internet-Scale Prefix Cache Sharing in LLM Serving
论文链接: https://arxiv.org/abs/2610.24179
发布时间: 2026-10（arXiv 2610.24179）
类别: cs.DC（POMACS）
代码: 暂无公开仓库
论文总结: KV 缓存复用目前局限于单集群，跨地域部署时各区域会重复 prefill 相同热门前缀。本文指出跨地域 KV 缓存发现比常规对象查找更难：缓存随请求到达与淘汰动态变化，位置无法像 DHT 那样由哈希键确定，需将缓存身份与放置解耦。KVCompass 作为发现平面支持变长前缀查找，在边缘以常数时间本地表读完成检索，并综合复用收益、负载与网络距离转发请求。64 worker 跨地域仿真与三大洲 14 worker 实机测试中，P99 TTFT 较基线降低 1.3 至 14 倍，吞吐最高提升 4.7 倍。
亮点: 首次把 KV 缓存发现抽象为互联网规模前缀共享缺失的"发现平面"层，让复用收益突破单集群边界。
三、推理 Infra 相关学术论文
1. A Hybrid GPU and Processing-Near-Memory Architecture with Shared DRAM for Efficient Prefill-Decode Disaggregation
论文链接: https://arxiv.org/abs/2610.26131
发布时间: 2026-10（arXiv 2610.26131）
类别: cs.AR
代码: 暂无公开仓库
论文总结: PD 分离虽消除了 prefill 与 decode 的相互干扰，但计算型 prefill 闲置内存带宽、访存型 decode 闲置算力，资源利用率低下。本文提出 DuoPD 架构：在 HBM 逻辑 die 中集成轻量近存处理（PNM）单元，通过共享 HBM 接口的 TSV 级带宽共享机制，让 decode 完整在 PNM 上执行，与 GPU 上的 prefill 并行且互不干扰。配合紧凑的 PNM 微架构与面向混合执行的分层数据映射方案，服务器级 LLM 评估显示端到端吞吐较传统 PD 分离最高提升 2.23 倍。
亮点: 用近存处理单元承接完整 decode 阶段，让 GPU 专心跑 prefill，在同一套内存上同时喂饱算力与带宽。

五、Vibe Coding Nice Practice
问题描述: 纯 vibe coding 把需求留在聊天记录里，结果不确定、难复现，改 prompt 容易推翻早前决定，项目变大后架构脆弱，Agent 也难以安全完成大任务。
具体做法: 采用轻量级 spec 驱动开发：动手前先在仓库写 requirements.md 明确需求与约束；让 Agent 依此生成 design.md 并由人审核；再把设计拆成带编号的 tasks.md，Agent 一次只实现一个任务并跑对应测试，通过后勾掉再进下一个。人负责决策与审查，AI 负责实现，需求与代码解耦后迭代不再互相破坏。参考 GitHub Spec Kit 等工具可直接落地。
