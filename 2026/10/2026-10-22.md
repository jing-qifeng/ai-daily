1. UlaCache: Unified Logical Addressing for Sparse LLM Serving
论文链接: https://arxiv.org/abs/2610.29820
发布时间: 2026-10-21
类别: cs.DC 分布式、并行与集群计算
论文总结: 稀疏注意力通过挑选历史 token 降低计算与内存开销，但被保留的 KV cache 须在后续解码步中持续可用。UlaCache 构建了跨 GPU KV 池与可选 CPU 内存的统一逻辑地址空间，稳定逻辑引用让 KV 分配与选择独立于物理布局，统一接口同时支持数据并行与张量并行注意力；启用 CPU 存储时用 PB-LRU 并行管理跨请求共享的 GPU 池。在匹配内存预算并开启投机解码时，H200 峰值解码吞吐较基线提升 1.16 倍（DP）与 1.70 倍（TP），B300 上达 1.73 与 2.51 倍。
亮点: 用统一逻辑地址空间把稀疏注意力的 KV 选择与物理放置解耦，B300 张量并行解码吞吐最高提升 2.51 倍。

二、KV Cache 复用相关学术论文
1. Cache Engineering for Agents
论文链接: https://arxiv.org/abs/2610.28577
发布时间: 2026-10-20
类别: cs.CL 计算语言学
代码: https://github.com/thu-nics/AKV
论文总结: LLM agent 的长轨迹使 KV cache 的 I/O 与存储成为主导成本，传统上下文工程靠裁剪或摘要缩减历史，却会使后续缓存失效并触发昂贵的重 prefill。本文提出 cache engineering：agent 用 drop 把选定缓存排除出未来注意力、用 repos 调整保留键的位置编码，直接控制活跃缓存而不改动轨迹；并设计 AKV 服务引擎，以无状态接口管理有状态的复用、驱逐与恢复。工具响应滚动 drop 策略使平均分提升 1.7 分、成本降低 27.7%，吞吐最高 1.2 倍，P95 延迟加速 1.5 倍。
亮点: 让 agent 以 drop 与 repos 原语直接操作 KV cache，AKV 引擎化解缓存操作序列导致前缀匹配失效的服务难题。

三、推理 Infra 相关学术论文
1. Prorsa: Unleashing the Potential of Prefill-Decode Disaggregation in Agentic Reinforcement Learning
论文链接: https://arxiv.org/abs/2610.16592
发布时间: 2026-10-12
类别: cs.DC 分布式、并行与集群计算（cs.LG 机器学习）
论文总结: Agentic RL 的多轮交互在 rollout 中不断引入 prefill 请求，使 prefill 与 decode 负载全程共存。论文证明 P/D 分离可通过缓解数据并行注意力模块间干扰、支持阶段特定并行、缩短轨迹完成时间来加速 rollout，但固定的资源分配难以应对负载构成的变化。Prorsa 观测每条轨迹的生命周期，预报短期 prefill 与 decode 需求，据此指导 worker 分配并触发引擎角色切换，在同步与异步设置下较 prefill 与 decode 混合部署取得 1.11 至 4.05 倍的端到端加速。
亮点: 把 P/D 分离从在线服务引入 agentic RL rollout，用轨迹级需求预测动态调整 prefill 与 decode 资源。

五、Vibe Coding 的 Nice Practice
1. 事先划定 AI 可独立构建与必须有人负责的代码边界
问题描述: vibe coding 的产出速度往往快于团队评审能力，若认证、支付逻辑等敏感代码也进入无人监督的生成范围，一个看起来能跑的登录流程上线后将成为最难撤销的事故。Gartner 预计 2028 年 40% 的企业新生产软件将采用 vibe coding 技术，而 Veracode 2026 年测试发现约 45% 的 AI 生成样本仍含已知安全缺陷，评审纪律必须同步跟上。
具体做法: 在写出第一个提示之前，先写下清晰的边界清单：内部原型、低风险页面等划入 AI 可无人监督生成的绿区；认证、支付、涉及合规数据的代码划入红区，必须有具名的人类负责人签字才能上线，并把该边界写进团队文档而非事后补规则。同时坚持每个 AI 生成的 PR 走与人类代码相同的评审流程，在 CI/CD 中挂上不可跳过的安全扫描，作为提示之外真正拦截问题的那道闸门。
